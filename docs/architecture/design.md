# 目标架构

本页写迁移方向。每节标出**已落地**的部分，其余都是**目标，尚未实现**。今天的行为读 [current-state.md](current-state.md)，不能按本页假定已有接口。

## 为什么这样设计

目标是让改一个模块的人（或 AI）只需读这个模块和它依赖的接口头：契约稳定、边界由护栏机检，多个模块能并行修改而不互相踩。所以每条规则都要能被检查脚本判定，而不是靠约定。

## 确定性推进

一次 tick 是一个模拟日，有明确的输入与提交结果。种子、初始内容版本和有序命令日志决定结果；帧率、后台线程唤醒、分片预算只决定什么时候完成，不能决定业务结果。同一天重试必须沿用冻结输入和请求身份。

顺序为：冻结输入（Freeze）→ 按模块依赖计算（Plan）→ 完成跨域请求（Resolve）→ 所有者提交（Apply）→ 发布已提交视图（Publish）。

### 单一时间线与前后台分工

后台独占一条模拟时间线，执行全部模拟判断、计算、跨模块交接和状态写入。前台只读后台发布的内容，
把玩家请求转发给后台，并用发布内容绘制画面、排版界面和生成展示文案。

1. **状态只有一份。** 十二域、军事、视野、资源恢复、家族都归后台模拟所有。前台读取只读的发布数据。
2. **逐日结果可复现。** 第 D 天的结果由上日状态和本日有序输入决定。后台使用自己的请求编号。
3. **命令由后台封口。** 前台转发玩家请求及显式指定的日期。后台依据约定的顺序和封口边界确认
   生效日。机器负载、帧率和界面刷新不能改变已确定的命令日期，也不能改变逐日结算。
4. **后台自己等玩家。** 后台判断何时需要玩家选择，到达该点时发布待处理事项并停在那里。
   前台展示已发布事项并转发选择。后台接受有效答复后续算，等待时间不改变模拟结果。
5. **每天发布一帧。** 提交时发布不可变的帧，界面读到的数据都属于同一天。
6. **正式模拟使用后台路径。** 同步执行用于测试和诊断对照。兼容路径的实际范围见
   [运行现状](current-state.md#前台尚存的模拟工作)。
7. **并行放在一天之内。** 后台任务分别计算各自的输出，由后台执行器按固定顺序完成跨域交接和提交。

迁移步骤与状态见 `docs/plans/execution-queue.md` 第 13 项。

**已落地**：十二域固定顺序表与 `static_assert`；`RuntimeFrozenInputVersion` 在 Climate、Country、Economy 登记；描述符 reads 推导的顺序检查（只报错，不重排）；四个请求队列共享入队与顺序键；三个 Apply 入口的写集合检查。

所有接管组合在开日时封口外来 Effect 登记、指标更新和退役。整批登记使用同一受理日，它取决于整日提交和已封口的日期。即使气候已预发多天，第 D 天封口后的请求仍在 D+1 受理，显式预约则在受理日与预约日中较晚的一天触发。登记与退役按实例编号处理，同一实例保留自己各次变更的顺序。同一受理日内，同实例同代只改预约日或失效日时，更新原队列位置。插入其他实例的请求不影响改约。退役、换代或改变生命周期字段会保留各次操作。存档使用同样的顺序。同日计算按实例编号递增分配事务号，指标值及其修订跟随所属实例。内联执行器等回执时也保留 Effect 的封口。开日封存此前收到的回执，处理登记和指标的耗时不影响旧事务的重送日。同日续算可处理当天发出的事务，以及已封口 Country 请求正在等的原事务回执，经济沿用已完成的结算。开日和初始日共用带范围检查的封口编码，超出可表示范围时报错并保留已提交日。Effect 按自身的提交日期识别重访，Modifier 内嵌 Effect 时也使用同一规则。新的事务命令随整日事件发布一次，重送沿用首次触发的参数。取得 Events 授权的会话首次启动和同世界重启都继续记事件。

**目标，尚未实现**：Climate 并入表内 Freeze（今天在表前提交）；通用纯 Plan；全域统一去重；全域原子提交与失败回滚；消除剩余软完成。

## 模块与接口

每个模块只经两扇门与外界交互：

- `<module>_api.h`：别的模块调用它。只放 POD、枚举、常量、前向声明和一行转发函数，不暴露运行时布局。
- `<module>_host_port.h`：它调用宿主。纯虚接口，签名与宿主方法一致。

运行时由组合根（宿主 `native_simulation_*`、绑定层 `world_ext*`）构造和拥有。

**已落地**：Economy、Country、Modifier、Military 的接口契约；Economy、Country 的宿主端口；军事核心只依赖 `military_bridge.h`。见 [module-boundaries.md](module-boundaries.md#模块公开接口)。

Country 的国家级政治体制沿用上述接口：体制 stable id 与 capability bit 由 Country
拥有，Economy 只读取已提交并冻结的 `CountryReadView`。政治 UI 是 Country 体制快照与
Ideology 快照的组合视图，不形成新的每日调度域。

**目标，尚未实现**：Effect、Trigger、Ideology、Climate 的接口头；其余模块的宿主端口；组合根数量继续收缩。

## 跨模块规则

只允许两种交接：读取所有者发布的不可变视图；向所有者提交有明确结果的业务请求（intent）。请求包含稳定身份、目标、日期和去重信息，所有者决定接受、等待或拒绝。消费者不能持有另一模块的可写容器，不能绕过所有者补钱、改人口或发布伪成功。

**已落地**：10 条已提交视图，包括经济结算的冻结税率；Economy→Country 全部写入走所有者端口（直接写为 0）；23 个域对逐项登记。

**已落地**：Military 的玩家自动探路任务留在 `MilitaryCore`，只接收 Host 冻结的玩家 explored
副本并返回实际进入格的轨迹。整日执行器合并实际探路轨迹并计算物理视野。`MapData.explored_arr` 只接收发布副本。

**目标，尚未实现**：剩余读边（见 current-state）改为已提交视图；19 个待核查域对的逐函数语义审查。依赖棘轮冻结的现有债务不是永久许可。

## 模块描述符

**已落地**：`runtime_module_descriptor.h` 定义 id、域、阶段成员函数、reads/writes、是否限主线程；cadence、视图版本、intent 类型、store、存档段登记在 `runtime_module_contracts.json`，由 `check_module_contracts.py` 核对。

**目标，尚未实现**：由内核检查依赖与所有权、自动排序、禁止绕行。当前声明不等于访问隔离。

## 黄金回放

目标记录每拍每域的规范化状态摘要，链接前一天摘要、输入与命令身份；排除计时、地址和诊断次数；用重复运行、不同分片、保存恢复和不同线程方式验证同一条链。

**已落地**：五条固定链（开局账目、整体经济、七域投影、Country、表外推进者）；四条轨迹的保存续跑矩阵，包括 365 日与非零军队。

**目标，尚未实现**：完整十二域状态哈希；多种子、跨平台、实际战斗占领。运行时 SHADOW/parity 在覆盖充分前保留。

## 存档与显示

每个模块拥有版本化的保存段；恢复先检查完整性、内容身份和依赖，再安装状态。保存的必须是真实继续所需的数据，不能只存游标。

Effect 安装新快照时，目录事务保留原号。旧低号的拓殖事务与其撞号时，按远征身份迁号，并同步更新等待中的国家或经济回执和存档校验值。保留号段撞号、运河撞号和目录内重号均拒绝整份快照。EFP1 v4 和 v5 的下一个事务号必须大于现存编号，并留在目录号段可分配范围内或标记该号段已用尽。PKSR v6 必须声明并包含 ETQ2，即使四个待办队列都为空。读档在安装前校验指标编号、修订号及实例的指标位置。v5 可没有待办段，也可携带 ETQ1 或 ETQ2。ETQ1 在下一次可处理时交付。v5 的负修订号仅在已存实例与排队登记均证明该代次届时失效时保留为一次丢弃。即时转存 v6 也在原受理日丢弃一次。复用宿主读档时，已结束时间线的环境输入随之清除。只支持 PKSR v5 的读取器会拒绝 v6。

存档请求在整日提交后生成存档。后台和内联执行器都记录是否有一天尚未完成。部分授权且缺少当日环境时也使用这个标记。部分授权的后台在暂停期间收到保存请求时，输入齐备后完成已打开的一天，再交付存档并保持暂停。由外部气候输入驱动的后台在开日前确认过期帧，等到目标日输入才开始计算。

**已落地**：12 个 C++ 域的段契约（版本、恢复依赖、旧版拒绝）；Country、Economy 的脚本 provider 契约；开发期旧版明确拒绝。

**目标，尚未实现**：所有 provider 统一注册；统一的候选安装与世界级回滚。

Godot 对象、图像和 GPU 上传由主线程负责。显示从已提交结果及其变化标记刷新。
